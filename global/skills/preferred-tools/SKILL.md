# Preferred tools

Recall memories through the memory skill before comparing candidates. Tool preferences live under its `## Tools` heading.

If no memory covers this choice, interview the user before recommending anything. Ask only what affects this choice and future ones, such as their existing stack, hard exclusions, operating constraints, and which tradeoffs matter most.

Use recorded preferences as defaults, not as a reason to ignore project requirements. When memory does not cover a relevant tradeoff, ask a focused follow-up. Research current candidates from primary sources, explain departures from recorded preferences, and separate durable preferences from one-project constraints.

After the user chooses, propose any durable preference as a memory through the memory skill.
